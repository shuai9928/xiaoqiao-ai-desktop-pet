# 把小乔换成你的角色

[返回使用说明](GUIDE.md) · [文档导航](README.md)

小乔是项目提供的陪伴角色。你可以在自己的本机副本里换成自己有权使用的角色图片、贴纸、性格和声音。当前需要手动编辑素材与 JSON；没有一键导入角色的设置界面。先从简单静态替换开始，再调整五官和坐姿动作。

**许可先确认：**用自己的作品或获准使用的图片。项目随附的小乔立绘和贴纸没有额外授予修改、商用或再次分发权；本说明不是这批素材的再授权。请看 [素材授权说明](../ASSET_LICENSES.md)。AI 角色素材另受 CrossPet 的 CC BY-NC-SA 4.0 约束。

## 先退出、备份，再编辑

1. 从桌宠右键互动卡片的「场景与设置 → 退出」或托盘菜单正常退出。AI 角色可能先完成短暂告别，等窗口消失后再改文件。不要用批量结束 Python 的命令。
2. 把整份程序目录复制一份作为备份。备份里的设置、聊天和密钥属于个人数据，不要上传或分享。
3. 便携版编辑的是解压目录 **`DesktopPet/assets/`**，不是 ZIP 内的文件，也不是 `_internal` 里的依赖。源码版编辑仓库根目录的 `assets/`。
4. 保存 PNG 与有效 JSON，启动 `DesktopPet.exe`；源码版用自己的环境运行 `pet.py`。出错时正常退出，再从备份恢复。

请在备份副本中先试换图，不要同时启动两个常驻实例。代码里的制作脚本需要源码、Windows Python 和对应依赖；便携版无需安装 Python即可运行，但不能直接运行源码制作脚本。

## 立绘与秋千是两套图片，必须一起换

| 文件 | 用途与坐标 |
| --- | --- |
| `assets/main.png` | 启动必需的透明 RGBA 立绘。当前画布 906×1187；五官和部位坐标以这张图为基础。 |
| `assets/scene/girl.png` | 1254×1254 原场景画布上的人物层，作为制作和对齐参考。它的 `girl_bbox` 裁图应与 `main.png` 一致。**只换这张图不会改变当前秋千身体。** |
| `assets/scene/swing.png` | 秋千、绳、坐垫和人物合在一起的运行层。传统秋千场景使用它。 |
| `assets/scene/swing_studio.png` | 默认紧凑工作台实际优先使用的身体层，仍然包含人物与绳／坐垫。一定要同步替换，否则会继续显示旧人物。 |
| `assets/scene/static.png`、`book.png`、`crystal.png` | 其他场景层。保留时必须与场景画布和挂点对齐。 |
| `assets/scene/meta.json` | 场景原画的像素坐标与各层包围盒。 |

最容易验证的办法是维持现有透明画布和坐姿几何，使用自己制作的整套层：人物手握绳的位置、坐垫接触处和脚底对齐后，分别保存人物参考层和两个完整秋千层。不要把新人物简单盖到旧人物上，否则旧脸、手脚和边缘仍会露出。尺寸变化较大时，应重新制作绳与座面接触，不能靠拉伸脸或发光藏接缝。

`meta.json` 中：`size` 是整套场景画布尺寸；`pivot_l` / `pivot_r` 是左右绳顶挂点；`seat_line_y` 是座位高度；`face.eye_l` / `eye_r` / `mouth` 是场景画布中的眼嘴像素坐标。`bbox` 里的 `static`、`swing`、`book`、`crystal` 和 `girl_bbox` 使用 `[左, 上, 右, 下]`，右、下为裁图边界。包围盒必须装得下实际有效像素。

## 五官、点击位置和部位

编辑 `assets/config.json`。这里多数角色坐标是 **`main.png` 裁图内 0～1 的相对坐标**，不要把场景的 1254×1254 像素坐标直接填进去。

- `eyes.left` / `right`：左右眼中心；`size`、`skin_at`、`blur` 控制眼睑覆盖范围与肤色取样。眨眼画到脸外时，先纠正这里。
- `mouth`：嘴的位置。与 `meta.json` 的场景嘴坐标保持一致：先减 `girl_bbox` 左上偏移，再除裁图宽高。
- `rig.regions`：帽子、头发、脸、身体、裙子等部位的多边形；决定点哪里算摸头、弹帽尖，以及变形发生在哪。坐姿动作还依赖现有接触保护和网格模型，大幅改轮廓需进一步修改源码，无法只换图片得到通用动作。
- `hat_orbit`：`[中心x, 中心y, 横半径, 纵半径, 倾角度数, 参考图宽, 参考图高]`，前四项是参考图像素。无帽子时不要沿用原轨道；当前核心配置中的帽檐开关属于历史兼容偏好，若要完全移除该效果需要检查对应源码路径。
- `icon_box`：图标取景的 `[中心x, 中心y, 范围]` 相对值，避免图标裁掉新角色的脸；`sprite_h` 是显示高度基准。

其他独立的 `hat_layer.png`、`hair_layer.png`、腿部图层仍可能被兼容路径使用。换大幅不同的角色时，也应核对这些层，避免旧局部图像重新出现。

## 换图后的眨眼与呼吸

`assets/animations/` 的图片不能随意沿用：它们绑定原图 **RGBA 像素的 SHA-256**，不是只认文件名。眨眼还绑定 `eyes` 配置；`relief-body` 呼吸绑定 `swing_studio` 的原生裁图、`meta`、`rig.regions` 与接触几何版本。

图片或坐标不匹配时，运行时会拒绝整段预烘焙 clip，回退到现有程序眼睑／实时身体网格路径；不会把旧脸的局部动画贴到新图上。这不代表新图的五官已自动正确：仍要校准坐标。更换 `main.png` 会使眨眼 clip 回退；更换秋千层或对应几何会使呼吸 clip 回退，两种校验独立。

要在**自己的源码副本**恢复预烘焙：先校准图片、眼嘴、部位与接触，再运行制作脚本的预览模式检查，然后明确写入素材：

```powershell
py tools/bake_blink_clip.py --out outputs/my-blink
py tools/bake_relief_clip.py --out outputs/my-relief
# 确认预览没有错位之后再写入本机自用素材：
py tools/bake_blink_clip.py --write-assets --out outputs/my-blink
py tools/bake_relief_clip.py --write-assets --out outputs/my-relief
```

这两步重新生成 PNG 和对应 manifest，不要手改哈希来绕过校验。脚本沿用当前眼部画法与坐姿保护规则，并非自动生成任意角色的动画。

## 表情贴纸

当前包提供 18 张 `assets/expr/*.png`。在「场景与设置 → 设置 → 表情贴纸」开关中控制显示，默认开启；旧版本强制关闭的设置会在首次升级迁移一次，之后手动关闭会保留。

`assets/emotions.json` 把心情名映射到贴纸文件名列表，例如 `"happy": ["okay", "laugh", "hello"]`，不用写 `.png`。一次反应从对应列表选择一张，不是依次播放整套图。可用自己的透明 PNG 替换，建议文件名保持不变；也可同步修改列表。缺失的图片会被略过。贴纸显示在小乔角色列，不进入右侧工作台；AI 形态使用自己的姿态，不显示小乔贴纸。

## 性格、声音与可选聊天

- `assets/personality.json`：`name`、`identity`、`relationship` 和 `likes` 可按自有角色调整；`traits` 的 `cute`、`playful`、`clingy`、`tsundere`、`mischievous`、`smart`、`caring` 使用 0～1 数值。它们影响可选 AI 聊天提示，不会自动改变本地固定动作和每句互动台词。
- `assets/audio/*.wav`：本地反应音。保持文件名、有效 WAV 格式，并在文件中预先调整音量；没有匹配音频时静默跳过。换这些文件不会改变聊天朗读声线，后者由源码中的 TTS 配置控制。
- `assets/ai_config.json`：可选聊天服务。参考 `ai_config.example.json`，配置自己的 `enabled`、`api_key`、`model`。不配置时仍能用基础互动和工作状态。外观改变不会自动更换聊天模型；不要把密钥放进仓库、网站或分享包。

## 实际换图验证

本说明的步骤用项目自制的几何机器人测试图走过：在临时副本替换 `main.png`、人物参考层和两个秋千身体层，校准眼嘴和场景几何；实际生产 `SceneArt` 加载与窗口合成使用新图，原动画银行返回 `source_mismatch`，没有混入旧人物。测试只改临时副本，未替换用户安装目录或个人数据。

源码中可复跑 `py tools/release/test_customization.py --out outputs/customization`，生成测试图、实际合成画面和 JSON 结果。它验证手动资源替换与可靠回退，不能代替你的角色在真实桌面尺寸下的视觉验收。检查眼睛、帽子、手与绳、坐垫接触、贴纸和工作台是否互相遮挡；再试拖动、滚轮缩放、摸头和正常退出。
